# 2026-06-03 — Static Dashboard Worker: KV HTML + Data Pattern

## Problem
The Agentic OS dashboard had two concurrent dashboards:
1. **TanStack SPA** (`dist/server/index.js`) — deployed via `wrangler deploy`, uses bundled `live-data.json`
2. **Worker.js** — separate static HTML file, should serve from KV

Both showed empty data. Root causes were different for each.

## Root Cause Analysis

### Issue A: Worker.js embedded HTML too large
- Worker.js contained the full HTML dashboard inline as a JS string (~15KB after minification)
- `wrangler deploy worker.js --name tanstack-start-app` fails: `"multipart: message too large" [code: 10021]`
- Even at 16KB raw, wrangler's multipart upload exceeds Cloudflare's limit because the platform also uploads `dist/client/` assets
- **Fix**: Store HTML in KV (`dashboard-html` key), keep worker.js small (<2KB), serve HTML from KV

### Issue B: wrangler deploy uses TanStack config, not worker.js
- `wrangler deploy` reads `dist/server/wrangler.json` (generated by Vite from `wrangler.jsonc`)
- That config has `"main": "index.js"` and `"assets": {"directory": "../client"}`
- It **ignores** `worker.js` unless you explicitly pass it AND override the assets
- Even `wrangler deploy worker.js` still bundles the assets directory
- **Fix**: Remove or empty `assets` from deploy config, or use `wrangler versions upload` API directly

### Issue C: KV "live-data" was empty
- The aggregator (`bun run scripts/aggregate.ts`) writes `src/data/live-data.json`
- But nobody was running `wrangler kv key put` to sync it to KV
- Worker returned `"{}"` as fallback → dashboard showed all dashes
- **Fix**: Add KV upload step after every aggregate+build

### Issue D: Worker JS used wrong data paths
- Old worker code: `d.meta.generatedAt`, `d.dailyUsage` (object)
- Live-data.json actual: `d.generatedAt`, `d.daily` (array)
- Also had typo: `document.getElementById('last-upported')` (missing 'd')
- **Fix**: Match actual live-data.json schema

## Working Architecture (Post-Fix)

```
VPS                              Cloudflare
─────                            ─────────
aggregate.ts ──→ live-data.json ──→ KV ["live-data"]
                                    KV ["dashboard-html"]
                                    ↓
worker.js (small, <2KB) ─────────→ serves HTML from KV
                                    serves /data/live-data.json from KV
```

## deploy-dashboard.sh Recipe

```bash
#!/bin/bash
set -e
export PATH="/root/.bun/bin:$PATH"
source /root/.profile 2>/dev/null

cd /code/agentic-os

# 1. Aggregate fresh data
bun run scripts/aggregate.ts

# 2. Build SPA (also produces worker entry)
bun run build

# 3. Upload live-data.json to KV
LIVE_DATA=$(cat src/data/live-data.json)
wrangler kv key put --binding=LIVE_DATA --remote "live-data" "$LIVE_DATA"

# 3b. Upload dashboard HTML to KV (if using KV HTML pattern)
# wrangler kv key put --binding=LIVE_DATA --remote "dashboard-html" "$(cat dashboard.html)"

# 4. Deploy worker.js
# NOTE: This only works if dist/server/wrangler.json has no assets directory
# and main points to worker.js. Otherwise wrangler bundles dist/client.
wrangler deploy worker.js
```

## Key Learnings

1. **Never inline large HTML in Worker.js** → use KV for HTML, keep worker <2KB
2. **Always verify KV has data** after `wrangler kv key put` → use `wrangler kv key get` to confirm
3. **Match actual JSON schema** — live-data.json uses `.daily` (array) not `.dailyUsage` (object), `.generatedAt` not `.meta.generatedAt`
4. **wrangler deploy != worker deploy** — wrangler always uses its config file; passing a different file doesn't override assets
5. **Cloudflare Worker + KV for static dashboards** is simpler than TanStack SSR for single-operator use cases
6. **`TanStack SPA bundle`** also works — it embeds live-data.json at build time. The SPA and Worker approaches are independent; pick one.

## TanStack SPA Approach (Alternative)

If using TanStack SPA instead of custom worker:
- `bun run build` bundles `src/data/live-data.json` into JS
- `wrangler deploy` uploads `dist/client/` + `dist/server/index.js`
- Data is baked in at build time — no KV needed
- SPA refreshes data only on rebuild+redeploy
- For live refresh, SPA calls `/data/live-data.json` which needs KV or a separate endpoint
