# Tanstack Start SSR — Cloudflare Worker Deploy Pattern

## Problem

Tanstack Start SSR apps build to `dist/server/index.js` which imports ES modules from
`dist/server/assets/*.js` (e.g., `./assets/worker-entry-CybWJ0-4.js`). These are NOT static
assets — they're ES modules that the worker runtime must be able to `import()`.

##Root Causes of Deploy Failure

1. **Wrong `main` path**: `wrangler.jsonc` pointing to source (`src/server.ts`) instead of built output
   (`dist/server/index.js`). Wrangler can't find the entry point.

2. **Using `assets` config for ES modules**: Adding `"assets": {"directory": "..."}` tells wrangler
   to treat the directory as Workers Sites static files. Static files are served at URLs, NOT
   importable as ES modules. The worker's relative `import` fails with error 10021:
   `No such module "assets/worker-entry-*.js"`.

3. **No module rules**: Without explicit `rules`, wrangler doesn't discover the JS files in
   subdirectories and only uploads `index.js` (0.10 KiB).

4. **Conflicting wrangler configs**: `.wrangler/deploy/config.json` (from wrangler's state) and
   `dist/server/wrangler.json` (generated by Vite build) can override the project root config.

## Correct wrangler.jsonc

```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "name": "your-worker-name",
  "compatibility_date": "2025-09-24",
  "compatibility_flags": ["nodejs_compat"],
  "main": "dist/server/index.js",
  "no_bundle": true,
  "rules": [
    { "type": "ESModule", "globs": ["dist/server/assets/**/*.js"] }
  ]
}
```

## Deploy Checklist

```bash
# 1. Build
export PATH="/root/.bun/bin:$PATH"
cd /root/code/<repo>
bun run build

# 2. Fix wrangler.jsonc if needed
#    - main → dist/server/index.js (NOT src/server.ts)
#    - no_bundle → true
#    - rules → ESModule globs for dist/server/assets/**/*.js
#    - NO "assets" config key (that's for Workers Sites)

# 3. Remove conflicting configs
rm -f .wrangler/deploy/config.json dist/server/wrangler.json

# 4. Deploy
wrangler deploy
```
